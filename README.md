# OpenGOAL Launcher

The OpenGOAL Launcher is a desktop application that installs, updates and runs the native PC ports of Jak and Daxter: The Precursor Legacy, Jak II and Jak 3. It also installs community mods and texture packs.

This repository is a fork of the original launcher. The README of the original project is kept in [original_project_readme.md](./original_project_readme.md).

## 1. Features added in this fork

### Saves Manager

One screen that lists the saves of the base game and of every installed mod, for each game. It shows them by region folder and slot, and lets you copy, move, back up or delete a save. Overwritten saves are backed up automatically, and transfers between different regions are refused.

Open it from the **Advanced** menu of a game or a mod, with **Open Saves Manager**.

Full guide with screenshots: [docs/features_ai/features_save_data_manager.md](./docs/features_ai/features_save_data_manager.md)

### Mod Texture Packs

Texture packs now work for mods, not only for the base game. Each mod has its own list of enabled packs and a **Texture Packs** page. When a mod source declares packs for a mod, installing or updating the mod downloads and enables them. Textures are copied into the mod's folder only, so the base game and other mods are never affected.

Open it from the **Texture Packs** button on a mod page.

Full guide with screenshots: [docs/features_ai/feature_modTextures.md](./docs/features_ai/feature_modTextures.md)

## 2. How the launcher works

The launcher has three layers:

- The interface, written with [Svelte 5](https://svelte.dev/), [Tailwind CSS](https://tailwindcss.com/) and [Flowbite Svelte](https://flowbite-svelte.com/), built with [Vite](https://vitejs.dev/). Code is in `src/`.
- The backend, written in Rust with [Tauri v2](https://tauri.app/). It reads and writes files, starts programs and keeps the settings in `settings.json`. The interface talks to it through Tauri commands. Code is in `src-tauri/`.
- The [OpenGOAL](https://github.com/open-goal/jak-project) tools, which the backend runs as separate programs: `extractor` reads the game disc, `goalc` compiles the game code, and `gk` runs the game.

### Installing a game

The launcher does not ship the games. You provide a PlayStation 2 disc image (ISO) of a game you own.

1. You select the ISO.
2. `extractor` checks the image, extracts its assets and decompiles the game code.
3. `goalc` compiles the result into data that the PC version can load, in the active data folder of the game.
4. `gk` starts the game when you click **Play**.

### Mods

A mod source is a JSON feed (`index.json`) that lists mods, their versions and download links. Its format is defined in [schemas/mod-source/v1/](./schemas/mod-source/v1/). You add sources in the launcher settings.

1. The launcher reads the feeds and shows the mods in the **Mods** list.
2. **Install** downloads the mod archive and extracts it to `<install dir>/features/<game>/mods/<source>/<mod>/`.
3. The mod's settings and saves go to `<install dir>/features/<game>/mods/<source>/_settings/<mod>/`.
4. **Play** starts `gk` with `--config-path <mod settings folder>`. This keeps the mod's settings and saves apart from the base game.

### Texture packs

A texture pack is a ZIP file of PNG images that replace in-game textures.

- Packs for the base game are extracted to `features/<game>/texture-packs/<pack>/` and copied into the base game data folder, `active/<game>/data/custom_assets/`.
- Packs for a mod are copied into the data folder of that mod only, `features/<game>/mods/<source>/<mod>/data/custom_assets/`.

After the textures change, the launcher decompiles the game again, and compiles it for mods, so the engine loads the new textures.

## 3. Development

Install [Rust](https://www.rust-lang.org/tools/install) and Node.js (LTS), then run from the root of the repository:

```bash
npx yarn install        # install the frontend dependencies
npx yarn tauri dev      # run the launcher with live reload (Rust and Svelte)
npx yarn typecheck      # check Svelte and TypeScript types
npx yarn check-format   # check formatting with Prettier
npx yarn test           # run the frontend tests
cd src-tauri && cargo test   # run the Rust tests and regenerate the TypeScript bindings
```

The files in `src/lib/rpc/bindings/` are generated by `ts-rs` when `cargo test` runs. Do not edit them by hand.

### Automated checks

Four GitHub Actions workflows are defined in `.github/workflows/`:

| Workflow       | File           | Runs on                                                                    | What it does                                                                                         |
| :------------- | :------------- | :------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------- |
| Build          | `build.yaml`   | Pushes and pull requests on `main` and `master-dev`, `v*` tags, manual run | Builds the app on Linux, Windows, and macOS (Apple Silicon and Intel).                               |
| Linter         | `lint.yaml`    | Pushes and pull requests on `main` and `master-dev`, manual run            | Runs `yarn typecheck` and `yarn check-format`, then `cargo fmt --check` and Clippy.                  |
| Tests          | `test.yaml`    | Pushes and pull requests on `main` and `master-dev`, `v*` tags, manual run | Runs `yarn test`.                                                                                    |
| Create Release | `release.yaml` | Manual run                                                                 | Bumps the version (patch, minor or major), tags it, builds the installers and publishes the release. |

More detail: [docs/github-workflow.md](./docs/github-workflow.md)

## 4. Getting help

When you report a problem, attach a support package. Generate it from the launcher settings. It bundles the logs and basic information about your system.

![Support package button in the launcher settings](./docs/support-package.png)

If the launcher does not start, the logs are in:

- Windows: `C:\Users\<USER>\AppData\Roaming\OpenGOAL-Launcher\logs`
- Linux: `/home/<USER>/.config/OpenGOAL-Launcher/logs`
- macOS: `/Users/<USER>/Library/Logs/OpenGOAL-Launcher/app/logs`
